# M02 FreeCAD 回流与版本差异验收

2026-10-23。Ubuntu 使用本机已验证的 FreeCAD 1.1.4，无需 SolidWorks。建模工作台将当前 STEP 装配与用户选择的 FCStd 转换结果进行只读比较；按原名或唯一几何签名重关联零件，报告体积、质心、尺寸变化。实体个数/面数改变、零件丢失、新增或匹配歧义均显示冲突，不提供接受操作；原 CAD 版本与 Link/关节编辑不被自动覆盖。无冲突时仍需用户明确点击接受，所有关节确认状态清零。

正式 `.venv/bin/python scripts/accept_phase.py M02`：**2/2 gate 通过，0 failed，0 skipped**。真实 FreeCADCmd 创建 base、resized、renamed、topology 四种 FCStd，经 FreeCAD 导出 STEP 并由独立 CAD 读取器重载。尺寸改变保持同名零件映射，唯一几何签名支持改名关联；给 Arm 增加孔后 `topology_changed` 冲突，原映射及 baseline hash 不变；旧 SHA 拒绝。CLI 返回结构化冲突 JSON。Electron 从空项目建 2 Link/1 Joint、导出 URDF ZIP，再选择匹配的 FCStd 人工接受，核对关节需重新确认；随后选择拓扑改变的 FCStd，UI 禁止接受。关闭并以同一用户目录重启后，已接受的 STEP/hash/配置仍恢复，关节仍未确认。机器报告 `artifacts/acceptance/M02.json`；桌面日志、截图和重启日志在 `artifacts/M02/desktop/`。

C04 **3/3**、M01 **2/2** 回归通过；TypeScript/Vite 生产构建退出 0。来源：官方 FreeCAD 1.1.4 AppImage 与 SHA-256 见 `docs/acceptance/C04.md`；参数化 CAD 和 C02/C03 物理导出边界见相应验收记录。

限制：这是几何层的 FCStd→STEP 回流，不保存/合并 FreeCAD 草图、约束或特征历史。面数/实体数是保守拓扑冲突信号，不能证明几何或机械功能等价；同拓扑的体积变化仍要求人工审阅。冲突需在 FreeCAD 修正或用“转换”工作区重新分组，本阶段没有自动推断新的关节。仅用自制两零件夹具验证，复杂用户装配仍需实测；RobotCAD 插件为可选来源，未单独安装/验证。训练适用性未知。
