# A02 CLI 与 MCP 工具接口验收

2026-10-23。新增同一受限 dispatcher 供 `urdftools tool` JSON CLI 与 `urdftools mcp` stdio 使用。公开四项工具：工作区内 URDF/ZIP/文件夹导入、A00 CAD 配方隔离预览、STEP 零件与关节发现、URDF ZIP 的独立 MuJoCo 物理验证。模型工具不提供直接应用或任意命令执行。CLI 与 MCP 共享 `schema_version/status/tool/data|error` 信封和错误码；MCP `tools/call` 的 `structuredContent` 与文本 JSON 完全一致。

权限：启动时由用户提供工作区根目录；工具参数仅接受相对路径，拒绝 `..`、绝对路径、反斜线、冒号、悬空路径及符号链接逃逸。导入/预览的内部存储目录也检查解析后仍在根目录内。子进程固定为项目 CAD/仿真解释器与固定脚本，不接收任意命令、模型服务地址或 API 密钥。

正式 `.venv/bin/python scripts/accept_phase.py A02`：**1/1 门禁通过、0 失败、0 跳过**。真实多模型 ZIP 导入返回 `selection_required`，真实双零件 STEP 检查返回 2 个零件，真实 CAD 建议预览增加 Arm 质量而 `current.json` 字节不变；真实 URDF/ROS ZIP 用 MuJoCo 校验为 2 Link/1 Joint。CLI 与 MCP 对同一 STEP 检查返回相同信封和数据；未知工具、`../`、指向工作区外的文件与内部存储符号链接均被拒绝，CLI/MCP 错误信封一致。第一次本地测试误把多模型 ZIP 期待为 `ready`，已修正为 `selection_required` 并重跑；正式记录见 `artifacts/acceptance/A02.json`、`artifacts/A02/runs/`。

MCP stdio 目前实现 **2025-06-18 初始化协议**，客户端可通过旧协议连接；新版 2026-07-28 的 `server/discover` 协议尚未实现，新版客户端需支持降级。协议行为依据 [MCP 官方 SDK stdio 文档](https://ts.sdk.modelcontextprotocol.io/v2/serving/stdio) 和 [协议版本说明](https://ts.sdk.modelcontextprotocol.io/v2/protocol-versions)。此阶段的“评估”仅为物理包验证，不宣称已完成强化学习适用性分析或训练结果比较。未提供远程 MCP HTTP 服务，用户文件不上传。
